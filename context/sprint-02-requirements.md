## What Was Built

### Stack (documentation reconciliation vs. earlier docs)

The architecture doc (written against SDK 53) and Sprint 01 doc (SDK 54) predate scaffold time. Actual versions used — latest stable at scaffold time:

| Package | Doc said | Actually used |
|---------|----------|---------------|
| expo | 53/54 | ~56.0.9 |
| react / react-native | 19.0/0.79 · 19.1/0.81 | 19.2.3 / 0.85.3 |
| react-native-reanimated | ~3.x | 4.3.1 (+ react-native-worklets 0.8.3) |
| @shopify/react-native-skia | ^1.x | 2.6.2 |
| expo-audio | ~0.4.x | ~56.x (SDK-versioned) |
| react-native-gesture-handler | ~2.24.0 | ~2.31.1 |

Additional deps not in the original list: `expo-router` (+ screens/linking/constants, required by the `app/` layout in the Sprint 01 structure), `@react-native-community/slider`, `expo-asset` (peer dep of expo-audio), `expo-splash-screen`, `react-native-web` + `react-dom` (web target).

Other divergences:
- **Gestures:** manual RNGH gesture port instead of `Gesture.Simultaneous(pan, pinch, rotation)` — see ADR-006.
- **Assets:** sounds and icons are procedurally generated by checked-in scripts — see ADR-007. Sound payload ~130KB (doc estimated <50KB).
- **Tuner panel:** the prototype's "State" readout (knob position / extension %) was intentionally omitted — it would require per-frame JS-bridge traffic for a debug nicety.
- **Physics timestep:** the prototype integrates per-frame at ~60fps; the worklet normalizes `timeSincePreviousFrame` to a 60fps step (clamped 0.25–2×) so 120Hz devices feel identical.

### Sensory event flow

The only JS-bridge crossings in the run loop, all via `useAnimatedReaction → runOnJS` in `app/index.tsx`:
- `clickEvent` counter (extension crosses 0.2/0.5/0.8) → click sound + light haptic (rate-limited 80ms / 60ms)
- `releaseEvent` counter (release with kz > 20px) → spring-release sound + medium haptic
- `mode` idle→active → selection haptic
- `userSpinVel` quantized to 2.5°/frame buckets → whoosh loop volume (only fires when the bucket changes)
